# 時間が層になり、束になる振り返り

2026-11-21 JST / #262。前回Cの柔らかな円を、実際の量に応じて層が増える表現へ進める。本人の依頼は「積み重ねの概念がないB/C」への改善デモで、製品採用は未決定。

## 新案「重なる余白」

`/reflection?look=layers`。初期は30時間＝1日分＋6時間。立体的な円の層で1日分と6時間を表示し、数字の下の内訳と対応させる。時計の針・カウントダウン弧は使わない。

- 薄い1層は1時間。24時間で1日分へ束ねる。1日分は1枚のまとまりとして残る。
- 30日分で月、365日分で年の束にする。月/年は目安として「約」を付ける。12か月＝360日を1年へ切り上げない。
- 端数を消さない。438日分は365日分の束1つ、30日分の束2つ、1日分13枚。1時間未満も端数の層と数値で残す。
- 束・層は省略せず描き、密な積み重ねは間隔を詰めて収める。厚さ/面積/体積は時間への比例尺ではなく、異なる束を読み分ける造形。量は個数・単位・数値で示す。
- 数字は既存の「まとまった大きな単位＋端数」、正確な時間の展開、全記録累計/週月内訳、節目と同じ値から生成する。

### 試す操作

上部はデモ専用の操作領域。「＋1時間を重ねる」で薄い層が1枚増える。「1回戻す」は直前の追加量を取り消す。月/年の場面では「＋1日分」に切り替わる。追加量は履歴として持ち、単位変更後も正確に戻せる。未記録からは追加できず、既知0分からは始められる。

操作欄は高さ280px以内でスクロールでき、文字拡大時も画面本体を塞がないようにしています。

「場面を切替」→「1日分になる直前」→「＋1時間を重ねる」で、23時間50分が1日分＋50分へ束になる。月/年の直前も同様に試せる。場面の選び直しで追加分をリセットする。元の案の20分比較ボタンは新案では隠し、追加操作に集約する。

束になるときは、前の層を縮めてから新しい束へ切り替える約310msの応答。通常追加は180msの短い到着表現。数値の更新や操作を待たせず、Reduce Motionでは即時に静止表示する。連打・場面切替・離脱で前のアニメーションを停止し、復帰は最新値を描く。自動加算/常時timerはない。

### 架空データと限界

追加操作はOSを操作せず、固定確認日2026/11/20までの合成日別記録を再生成する比較用のもの。1日最大4時間を保つため履歴の日付や節目も再構成され、実履歴への追記/保存ではない。この処理を製品実装へ流用しない。UTC日付キーのfixtureで、時差/DST評価器ではない。

制限を記録した時間を換算しており、実際の用途/有効活用/連続した休日を測っていない。未記録は—、既知0は0分、一部欠測は既知分のみ。解除を失敗と評価しない。
