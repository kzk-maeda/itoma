# NNNN: 判断のタイトル

- 状態: Proposed（Accepted / Rejected / Superseded）
- 検討Issue:
- 決定PR:
- 採用日: 未定（採用時にJSTの日付）
- 関連・置換するADR:
- 検証状況: 未実施 / 一部実施 / 条件付き確認（対象環境を明示）

## 背景と解決する問い

利用者の場面、既存の制約、判断が必要な理由。

## 選択肢と比較基準

少なくとも現状維持を含め、複雑さ・復旧・プライバシー・OS制約・検証可能性で比較する。

## 提案または決定

何を採用するか。Proposedの間は提案と明記する。

## 理由と影響

利点、欠点、採用しなかった案、影響するAPI・データ・画面・移行・実装Issue。

## 証拠と未解決事項

公式資料、確認日、PoCの対象SHA/ビルド/環境、未確認の仮説。計画を実績と書かない。

## 再検討条件

どのOS制約・PoC失敗・仕様変更が起きたら再検討するか。
