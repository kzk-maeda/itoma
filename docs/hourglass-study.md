# 砂時計を中心にしたUIの比較PoC

状態: ユーザー依頼の画面モック。アイコン候補10を起点にした別案であり、円形UIの正式ガイド・最終ロゴ・OSの実装仕様を置き換えない。[作業Issue #65](https://github.com/kzk-maeda/itoma/issues/65)。

## 入口と範囲

`demo/hourglass-experience` を最新main `6662cdf` から作成。既存のブランチ配信へ `public/hourglass.html`、`hourglass.css`、`hourglass.mjs`、`hourglass-math.mjs` を収録する。

- ブランチURLに `hourglass.html` を付ける（`npm run demo:info` でURL確認）。
- ローカル: `python3 -m http.server 8769 --directory public` → `http://localhost:8769/hourglass.html`。
- ページ外側の「ホーム」「一時解除」「解除中」でモックを切り替える。「解除中」はサンプル理由によるXの仮解除を用意するデモ操作であり、製品の解除入口ではない。
- 「10分進める」「解除の期限へ」「23:00へ進める」「状態不明を試す」はデモの時計/状態だけを変更する。時計は21:30から進む。
- 円形UIの「墨と白」の既存デモへの比較リンクは別タブで開く。既存デモ・共有インフラ・workflowは変更しない。

## 砂時計を使う体験

| 画面 | 砂時計の意味 | 主情報と操作 |
| --- | --- | --- |
| ホーム | 夜の時間帯21:00–23:00の残り。上がこれから、下が経過 | ルール名、残り1時間30分、23:00終了、本人の目的、対象ごとの状態、共通の一時解除入口 |
| 選択・理由 | 砂時計の絵を繰り返さず、今の意思へ集中 | アプリを1つ選択、自分の言葉で理由を入力。空白不可。戻る/継続時は破棄確認 |
| 内容確認 | 確定内容を優先し、絵で判断を邪魔しない | 対象、理由、最大5分と23:00の上限、残る制限を説明して確定 |
| 一時解除中 | 選択アプリの今回の解除期間だけの残り | 「YouTubeの一時解除」等で意味を明示。残りm:ss、絶対終了時刻、理由、早期終了/ホーム。夜のルールは別の小さな要約 |
| 時間帯終了 | 砂時計を隠し、今回のルール終了を表示 | デモのX/YouTubeは制限なし。他の有効ルールはこのPoCにない |
| 状態不明 | 砂時計を止めた成功表示にせず、図自体を隠す | 設定上の期限と、反映を確認できないことを区別。再確認はモック結果へ戻す |

残りが少ないときに赤くする、砂時計を振る/反転する、追加待機、回数制限、課金、音、反復粒子の演出は足さない。「失った時間」「取り戻した時間」「集中達成率」とは表示しない。

## 視覚・動きの契約

- 基本色は採用された05「墨と白」のLight/Dark。文字・操作・引用面は [UIガイドライン](ui-guidelines.md) §6.1/6.4と同じ値。
- UI用の砂時計SVGは候補10に着想を得たモック用の再作図。柔らかさの調整では直線的な三角形と上下の硬い横棒を外し、器・砂・ブランドマークの肩とくびれを曲線にした。輪郭と砂の流れの線も淡くした。最終のアイコン/ロゴアセットへの採用や置き換えではない。
- 上下の砂を、丸い肩とくびれを持つ同面積の曲線形状でモデル化。Bézier輪郭を各区間64分割して面積を求め、24回の二分探索で上の残砂面積が残り割合rになる水準を算出する。下は上下反転した同形で面積1−rを保つ。SVGの描画と面積計算には同じ輪郭を使い、数値が示す残り時間は変更しない。
- 21:30では上75%/下25%、残り90分。数値の正本は時刻と期限であり、描画位置から時間を逆算しない。
- 砂の水準の変更は650msで補間する比較値。常時の粒子ループは置かず、流れを示す細線は静止。表示更新は実際のデモ時刻の差分に従う。
- Reduce Motionでは水準を補間せず更新し、移動/スケールを止める。設定変更時も実行中の動きを停止する。数字と読み上げラベルは同じ時間を示す。
- 非表示中は表示timerを停止。復帰時は現在時刻へ合わせる。JS timerや砂の描画をOSの再制限機能として扱わない。

対応する方向: 原則1〜5、U02〜U07、UI04〜UI09/UI14/UI16/UI23/UI30/UI35/UI36。円弧を指定したU05/UI02/UI28と異なる表現を試すための限定PoCで、正式ガイドを砂時計へ変更するものではない。

## 解除のモック仕様

- 対象はXとYouTube。1回に1つを選び、アプリごとに独立した期限を持つ。両方を解除した場合は「対象を一時解除中」とし、新規対象がないことを示す。
- 解除中の同対象は選べない。別対象の解除は可能。早期終了しても他アプリの解除を終了しない。戻る/見た目の切替で期限を延ばさない。
- 期間は確定時から最大5分・23:00まで。確認中も境界までの残りを更新する。ただし、採用済み設計の優先ルール切替・予定登録・command・OS観測は実装せず、2アプリ/単一ルールのメモリ内シミュレーション。
- 理由はデモ上200文字までで、空白だけを拒否する。最大長の製品採用ではない。内容は画面内メモリのみ、HTMLエスケープし、保存・送信・URL/ログ出力しない。
- 状態不明は、入力や期限を保持したまま通常の図を隠す。解除や早期終了の結果はモックの表示であり、実アプリが開ける/開けないことを意味しない。
