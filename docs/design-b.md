# B案の更新: 残り時間・自由入力・複数アプリの一時解除

状態: ユーザーのB案へのフィードバックを反映したWebデモ。OS動作・本体仕様の正式採用を宣言するものではありません。関連: [MVP検討 #21](https://github.com/kzk-maeda/itoma/issues/21)、[状態モデル #22](https://github.com/kzk-maeda/itoma/issues/22)、[競合ルール #23](https://github.com/kzk-maeda/itoma/issues/23)、[初期3案 #39](https://github.com/kzk-maeda/itoma/pull/39)。

## 入口

`public/design-b.html` は外部通信や追加依存のないWebプロトタイプです。`npm run demo:info` で確認したブランチURLに `design-b.html` を付けます。ローカルは `python3 -m http.server 8766 --directory public` を起動し、`http://localhost:8766/design-b.html` を開きます。

最新main（#37反映済み）から `demo/b-reason-unlock` を作成しています。配信workflowと手動配信ガードの `demo/**` 制限は変更しません。既存 #39 のブランチ・配信環境は変更・撤去しません。

## 反映した要望

- B案の紙のようなニュートラル背景・穏やかな緑・本人が登録した目的の引用を維持。
- 自由入力の解除理由を必須化。理由候補は並べず、空白だけでは進めない。内容の評価や過剰な文字数要求はしない。
- 円の中心に「制限終了まで1時間30分」と「23:00に終了」を集約。下部の開始・終了時刻と時間バーは置かない。
- 円の線は現在の制限区間の残り割合。21:00–23:00のうち21:30では75%。文字も併記し、色・円の見分けに依存しない。
- 制限対象のXとYouTubeのどちらも一時解除可能。アプリ選択→自由入力→対象・期間・理由の確認→確定とする。

本人が設定した夜のルールと「読書」の目的があるというサンプルです。時刻は21:30から実際の経過時間に合わせて進みます。アプリ名と理由はデモのサンプルを使い、OSから取得する仕様ではありません。

## 一時解除の入口の比較

| 方式 | 利点 | 注意点 | 扱い |
| --- | --- | --- | --- |
| ホームにアプリごとのボタン | 目的のアプリを直接選べる。2個程度なら一覧性がある | アプリが増えると解除操作がホームを占める。複数を使う用事の扱いが分かりにくい | 比較スイッチで操作可能。押したアプリを次画面で選択済みにする |
| ホームの入口は1つ、別画面で選択 | ホームの主役を残り時間と本人の目的にできる。対象数が増えても整理しやすく複数選択にも対応 | 単体の解除でも、対象を選ぶ操作が1つ増える | 通常の入口として推奨。最初は未選択 |

両方式とも同じ選択・理由画面に入り、アプリを追加・変更できます。比較スイッチは端末枠の外に置き、製品設定とは分けます。

将来、特定アプリの制限画面から来た場合は対象を引き継ぐ方法が候補です。ただし、iOS Shieldからの移動と対象の引き継ぎは別途技術検証が必要で、このデモでは実装・保証しません。

## デモの解除ルール

- 対象は明示的に選んだアプリだけ。初期状態で「すべて」を選択しない。
- 複数選択時は、今回選んだアプリに共通の理由を入力し、同じ5分間の解除として確認する。5分は仮値。
- 未選択のアプリは制限中のまま。確認画面でも継続する対象を明示する。
- 理由と選択は確認から戻って編集可能。キャンセルでは解除せず、下書きは破棄する。
- 解除は確定時から開始。早期終了と期限到達で選んだアプリを制限に戻す。23:00にルール自体が終われば制限なしにする。
- デモでは同時に1つの解除セッションのみ。解除中に新たな解除を重ねる操作は設けず、ホームから状況・早期終了へ進める。追加の解除・別々の期限・重複ルールは #22/#23 の後続検討。
- 理由は画面内メモリだけ。確認時にHTMLエスケープし、保存・送信・ログ出力しない。画面再読み込み・キャンセル・解除終了で破棄する。

## 検証

Chromium / Playwrightで以下を操作して確認しました。

- 未選択・未入力・空白のみで進めない。YouTubeのみ、Xのみ、両方を選択できる。
- 理由の確認・戻る・編集・キャンセル、個別ボタンからの対象引き継ぎ、選択を全解除したときの無効化。
- YouTubeのみ解除時にXの制限が続く。両方の解除、早期終了、自然な5分の期限到達（ブラウザ時計を進めて確認）。
- 解除中の入口比較スイッチは解除範囲・期限を変更しない。23:00ではすべて制限なしになり、解除操作が消える。
- 入力をHTMLとして解釈しない。ブラウザ例外なし。
- 残り時間の更新と開始時75%のリング。320 / 390 / 768 / 1200pxでホーム・入力画面とも横方向のはみ出しなし。Dark・Reduce Motion表示。
- 型チェック、lint、Jest 2件、デモツールテスト3件、expo-doctor 20/20成功。Webデモのビルドとpublic assetへの収録を確認。
