# はじめの余白 — オンボーディングのWeb PoC

状態: [Issue #115](https://github.com/kzk-maeda/itoma/issues/115)の画面比較。通常UIを土台に、キャラクターは体験を支えられる節目だけに登場させるという本人の方針を反映する。本体の初回起動/認可/保存の実装や、製品仕様の正式採用を意味しない。

デモ: https://itoma-demo.kzk-maeda.com/demos/demo-onboarding-experience-141cd546aebd/ （Cloudflare Access認証が必要）。`onboarding.html` でも開ける。

## 提案する流れ

最初に「使い方を覚える」より、自分のための時間を一つ決めることを目標にする。会話入力・アカウント登録・長いアンケート・通知許可を追加しない。

| 画面 | 本人が決めること | 設計の意図 |
| --- | --- | --- |
| 導入 | 設定を始める / 設定せずホームを見る | 一画面で価値と操作を伝える。相棒は小さく添える |
| 目的（任意） | 大切にしたいことを選ぶ/書く / あとで決める | 初期設定を文章入力で止めない。空ならホームの引用面も省く |
| 時間 | 曜日と開始/終了時刻 | フォームとプリセットで操作。設定の要約をその場で確認する |
| 対象アプリ | 許可の確認 / アプリ選択 / あとで設定 | 自分の時間を決めたあと、対象選択に必要な権限の理由を説明する |
| 最終確認 | 目的/曜日/時間/対象を見直し、本人が確定 | 許可や選択だけでは開始しない。未許可/対象なしは準備中として残す |
| 完了→ホーム | 設定状態を確認し、画面を離れる | 準備が整った場合だけ相棒が節目を支える。ホームは元のサークルUI |

外側のキャラクター表示をオフにして比較できる。キャラクターは導入と準備完了にだけ置き、時間/対象/権限/確認/ホームには登場させない。表示の有無でフォームや入力・許可状態・期限は変わらない。仮称「まる」の姿は前の相棒デモと同じ試作SVGで、正式なブランド資産の採用ではない。

## 許可・後回し・反映を分ける

- 許可の理由は「選んだアプリを、決めた時間だけ制限するため」。起動直後に自動で要求せず、アプリ選択の場面で本人が操作する。
- 許可ダイアログとアプリPickerは、自作の**モック**と明示する。実際のiOSシステム画面・生体認証を再現した証跡ではない。ユーザーが許可/拒否/取消を選んで流れを確認する。
- Pickerの変更は一時状態。取消では確定済みの対象を変えない。許可後も対象未選択なら開始しない。拒否後も目的と時間を保持し、後から続けられる。
- 未許可/対象なしの最終操作は「内容を残して、ホームへ」。準備中のホームには制限中の円を置かず、「設定を続ける」から再開する。同じ対象選択への重複した入口を並べない。
- 再許可では以前の選択を有効と見なさず、新しくPickerで確認し、最終確認を経て初めて開始する。自動で制限を再開しない。
- 設定の保存と制限の反映は別。外側で反映失敗/不明を注入すると、内容は保持しつつ反映未確認を明示する。結果を通常へ戻しただけでは適用状態を変えず、本人の再試行で確認する。
- 時間外なら予定のホーム、時間帯内で準備/反映が整ったモックなら残時間のサークル。拒否/失敗/不明に「おめでとう」や制限中の断定を出さない。

これは#36の認可・選択・Activation・設定・観測を区別する方針に沿ったUI表現。現行native PoCの権限/opaque選択/実機の保証をこの画面へ読み替えない。実装では#12/#13/後続の正式オンボーディング設計へ接続する必要がある。

## 操作・数値の範囲

- 月曜21:30の架空時刻。初期の時間候補は平日21:00〜23:00で、本人の確認前は有効設定ではない。曜日変更、時間入力、翌日にまたがる時間も試せる。
- 目的は任意/200文字、時間帯15分以上、対象はX/YouTube/Instagram/TikTokの4候補というデモ値。正式な制約やnative対象の識別子ではない。15分はDeviceActivityの検証条件を意識した候補で、ドメインの採用値を上書きしない。
- 各フォームの戻る/修正でdraftを保持し、確定済みprofileと分離する。未確定のままホーム/リセットへ離れると破棄確認する。ブラウザ戻るではメモリ内draftを保持。iOSの戻るgesture/再起動後復元は未実装。
- ホームの一時解除もアプリ1つ・自分の理由・確定前確認で操作できる。最大5分/時間帯終端で短縮し、再表示で延長しない。対象ごとに独立し、早期終了は選んだ対象だけ。入力中の閉じる/ESCも破棄確認する。
- 時間/対象の再設定で既存の解除が終わる場合は確認前に表示する。本体での競合・短縮・OS予定登録の実装とは別のモック。
- 設定・入力はページ内メモリのみ。再読込/リセットで初期化する。入力をURL/ログ/解析/ネットワークへ出さず、生成AIも使わない。

## 原則と見た目

05「墨と白」、OPEN CIRCLEの方向、余白、通常フォームを土台にする。導入の円と小さな相棒で親しみを添え、判断が必要な途中の画面は文字と選択へ集中させる。ホームは状態→円/予定→目的（登録時のみ）→対象→次の操作の順。

原則1〜5、U01/U02/U03/U04/U05/U06/U07/U08、UI01/UI02/UI04〜UI09/UI14/UI16/UI17/UI19〜UI26/UI28〜UI36に関連。全条件を本体で合格した宣言ではない。P07の目的保存先、初回フロー/最短時間などはこのPoCから自動採用しない。

Light/Dark、狭幅、文字拡大、Reduce Motionを使える。曜日の選択は文言と選択状態で示す。大きい文字ではサークルを小さくし数値を外へ置き、目的カードとの重なりを防ぐ。短い遷移と残時間の円だけを動かし、連続アニメーションや演出完了待ちを置かない。
