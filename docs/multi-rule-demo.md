# 複数ルールの状態と解除対象のデモ（#230）

2026-11-19 JST。本人依頼による表示改善案。main a880eea を基点に、実装の ProductHome / UnlockScreen / PeriodRing / Router を使う。demo/multi-rule-status から専用URLへ公開する。mainへの採用・実OS制御の変更ではない。

## 現状の問題と改善案

現状のホームは現在の区間・全保存対象・解除入口が分散し、解除画面も保存対象全件を列挙する。無効行が多くなり、今どのルールで何が制限されているか読み取りづらい。

1. 上部に現在時刻・制限中アプリ数・時間内ルール数・次の開始/終了予定。共通の一時解除入口をここに1つ置く。
2. 現在のルールごとにカードを作る。名前/開始終了/円の残時間/本人の目的/適用アプリと各状態をまとめる。複数時は円を小さくし、単独時は既存の大きな円を保つ。
3. アプリはnative snapshotの target.ruleID を参照して現在の適用先へ一度だけ表示する。JSで勝者を決めない。一時解除中はルールの残時間と混ぜず、アプリ行へ期限を表示する。
4. 今日のスケジュールを開始順に表示。時間終了/時間内/開始前、日跨ぎ、アプリ件数を示す。これは保存した壁時計設定のプレビューと明記し、OS適用成功とは扱わない。
5. 解除候補は認可・activation・予定準備・反映鮮度を満たす現在のnative区間の、restrictedかつunlockable、進行中commandなしの対象だけ。時間外/解除中のアプリを無効行として並べない。
6. 選択アプリに適用ルール・区間を併記。入力中に適用ルール/区間が切り替われば理由と時間を保持し、アプリだけ選び直す。確認後の変更も再確認し、native側の最終再検証を省略しない。
7. 不明/停止時は制限成功と断言せず、候補を出さない。空候補には状況と帰り先を伝える。

原則1/2/3/4、U02/U03/U04/U05、P02/P03、UI01/UI02/UI03/UI04/UI09/UI14/UI18/UI20/UI22/UI23/UI24/UI25に関連。予定表示はDST等でnativeが確定するinstantの代わりではない。本体採用時は全予定/次境界のnative DTO拡張を別レビューし、設定プレビューを唯一の発火根拠にしない。

## デモの操作

上部の「状態を変更」で次の架空状態に切り替えられる。実際の現在時刻と異なるデモ時刻を使用する（端末のローカル日付/時刻に合わせたfixture）。

| 状態 | 確認する内容 |
| --- | --- |
| 重複中 21:30 | 夜の自分時間: Instagram。読書に集中: X / YouTube。TikTokは解除候補に出ない |
| 単独ルール 20:30 | 夜の自分時間: X / Instagram。Xの解除期限は21:00の切替まで |
| 22時の切替後 22:05 | 夜の自分時間: Instagram。おやすみ前: X / TikTok。YouTubeは候補から消える |
| 時間外 19:00 | 制限中カード/解除入口なし。次の開始予定 |
| 一時解除中 21:30 | Xだけ解除中。Instagram / YouTubeを解除候補に表示 |
| 日跨ぎ 00:30 | 前日22時から当日7時までの区間。次の日の同ルールと区別 |
| 反映未確認 | 設定上の時間と反映未確認を区別。解除候補なし |
| 全体停止 | 停止を明示し、保存予定を制限中と表示しない |

候補を1つ選択→自分の言葉の理由→時間→確認→模擬解除→状況→ホーム。入力途中で上部から22時へ切り替えると、理由を残した再選択を確認できる。Webではnative Alertのcallbackをブラウザ確認へ代行する（デモフラグ有効時のみ）。

## 分離と検証

fixture/provider/toolbar は src/demo/multi-rule に分離。ITOMA_DEMO_BUILD=1 のextraフラグとWebの両方が必要。通常のWeb/iOSは実ポートを使う。架空app ID・名前・目的のみを使い、OS、実課金、永続保存、外部AIを呼ばない。再読込で模擬解除・入力は消える。設定の編集と振り返りのデータは今回のデモ範囲外。共有コンポーネントを使うが、本PR全体をそのままmainにマージする想定ではない。

作業環境が接続不能となったため、最終版は接続済みGitHub APIで同じmainから復元し、既存CIに加え本ブランチ限定の静的exportのブラウザ検証を配信前に実行する。型/lint/Jest/demo tools/Web exportと各コマンドの結果、配信SHA・URL・Version IDはPR/Issueに記録する。expo-doctorの外部照合は別結果として記録する。

ブラウザ検証の画像/JSONはActions artifact multi-rule-demo-qa に添付する。Light/Dark、狭幅、DOMの文字2倍、候補集合、単一アプリ解除、入力中のルール切替を確認する。DOM拡大はnative Dynamic Typeの代用合格ではない。Simulator/実機/VoiceOver/実際のgesture/Screen Time・Extension/永続化は未検証。自動画像の生成を人による目視レビューと同一視しない。
