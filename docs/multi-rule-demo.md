# 複数ルールの状態と解除対象のデモ（#230）

2026-11-19 JST。本人依頼による表示改善案。main a880eea を基点に、実装の ProductHome / UnlockScreen / PeriodRing / Router を使う。demo/multi-rule-status から専用URLへ公開する。mainへの採用・実OS制御の変更ではない。

## 現状の問題と改善案

現状のホームは現在の区間・全保存対象・解除入口が分散し、解除画面も保存対象全件を列挙する。無効行が多くなり、今どのルールで何が制限されているか読み取りづらい。

最新版は公開版5ccfcd0への本人追加依頼（2026-11-19 JST）を優先する。以下は比較デモの設計で、製品採用・OS動作の完了ではない。

1. ホームは現在状態→適用中ルールのカード→次の切替予定。**「今日のスケジュール」は表示しない。**
2. 複数ルールはカードを重ねて表示し、左へ送ると次、右へ戻すと前のルール。スワイプは閲覧だけで、停止/削除/好き嫌いの評価はしない。最後でループしない。単独ならスワイプとページ操作を省く。
3. 「1 / 2」とルール名・ページ印、44pt以上の前後ボタンを併設。見えていないカードの操作/読み上げ要素はmountしない。選択中のルールは作業画面から帰っても保持する。終了したルールを選び続けず、残る有効カードへ戻す。
4. 各カードに名前/区間/円形残時間/本人の目的/適用アプリと各状態/一時解除の入口をまとめる。複数時は小さい円、単独なら既存の大きな円。同じアプリはnativeの target.ruleID に従って一度だけ表示する。
5. **一時解除の入口はルールごと。** そのルールで現在制限中かつ解除可能な対象だけを選ぶ。別ルールのアプリ、時間外、進行中の要求は並べない。選んだルール名と時間は上部にまとめ、各候補へ繰り返さない。
6. 選択ルールIDをRAM内の入力draftに保持する（winning ruleの判定ではない）。確認/確定でも現在の適用範囲を照合し、nativeの最終再検証は維持する。URLへ理由を入れず、保存/bridgeの契約は変更しない。
7. 入力中にルールの適用が変わったら、アプリの選択をクリアし、理由/時間は残す。別ルールへ候補を自動で広げない。「ホームでルールを選び直す」は進行中previewの取消を確認してから入力を保持して戻す。次のカードから開くと新しいルールへ明示的に範囲を変更する。「制限を続ける」の破棄確認とは区別する。
8. 不明/停止時は制限成功と断言せず、カードに解除入口を出さない。過去のU02の共通入口案より、今回の本人指定を優先した比較。アプリ別ボタンをホームへ並べる構成にはしない。

### スワイプとモーション

- 横へ12pt超、縦より1.5倍以上の移動でカードがgestureを引き受ける。縦スクロールとタップを奪わない。
- 幅22%超、または18pt超かつ十分な横速度で次/前へ送る。小さな移動や中断は元へ戻す。動作対象は表示中のカードだけ。
- 操作中だけ横移動と最大5度の回転、送出170ms。背面の輪郭で複数カードを示す。回転/移動はReduce Motionでは使わず、同じスワイプ/ボタンで静止切替する。
- iOSはAnimatedのnative driver、WebはJS driver。新しいgesture/animation依存は追加しない。未保存/解除commandの状態をアニメーションから変更しない。

原則1/2/3/4、U02/U03/U04/U05、P02/P03、UI01/UI02/UI03/UI04/UI09/UI14/UI18/UI20/UI22/UI23/UI24/UI25に関連。次の予定表示はDST等でnativeが確定するinstantの代わりではない。本体採用時は全予定/次境界のnative DTO拡張を別レビューし、設定プレビューを唯一の発火根拠にしない。

## デモの操作

上部の「状態を変更」で次の架空状態に切り替えられる。実際の現在時刻と異なるデモ時刻を使用する（端末のローカル日付/時刻に合わせたfixture）。

| 状態 | 確認する内容 |
| --- | --- |
| 重複中 21:30 | 夜の自分時間: Instagram。読書に集中: X / YouTube。各カードから対応する対象だけを表示。TikTokは候補外 |
| 単独ルール 20:30 | 夜の自分時間: X / Instagram。Xの解除期限は21:00の切替まで |
| 22時の切替後 22:05 | 夜の自分時間: Instagram。おやすみ前: X / TikTok。YouTubeは候補から消える |
| 時間外 19:00 | 制限中カード/解除入口なし。次の開始予定 |
| 一時解除中 21:30 | Xだけ解除中。夜のカードはInstagram、読書のカードはYouTubeだけを候補に表示 |
| 日跨ぎ 00:30 | 前日22時から当日7時までの区間。次の日の同ルールと区別 |
| 反映未確認 | 設定上の時間と反映未確認を区別。解除候補なし |
| 全体停止 | 停止を明示し、制限中カードと解除入口を出さない |

候補を1つ選択→自分の言葉の理由→時間→確認→模擬解除→状況→ホーム。入力途中で上部から22時へ切り替えると、理由を残した再選択を確認できる。Webではnative AlertのcallbackをWeb用の確認ダイアログへ代行する（デモフラグ有効時のみ）。

## 分離と検証

fixture/provider/toolbar は src/demo/multi-rule に分離。ITOMA_DEMO_BUILD=1 のextraフラグとWebの両方が必要。通常のWeb/iOSは実ポートを使う。架空app ID・名前・目的のみを使い、OS、実課金、永続保存、外部AIを呼ばない。再読込で模擬解除・入力は消える。設定の編集と振り返りのデータは今回のデモ範囲外。共有コンポーネントを使うが、本PR全体をそのままmainにマージする想定ではない。

初版は環境切断に伴いGitHub APIで復元。その後は復旧したworkspaceで公開版へfast-forwardして追加依頼を実装し、既存CIに加え本ブランチ限定の静的exportのブラウザ検証を配信前に実行する。型/lint/Jest/demo tools/Web exportと各コマンドの結果、配信SHA・URL・Version IDはPR/Issueに記録する。expo-doctorの外部照合は別結果として記録する。

ブラウザ検証の画像/JSONはActions artifact multi-rule-demo-qa に添付する。Light/Dark、狭幅、DOMの文字2倍、左右の実touch dragと前後ボタン、ルールごとの候補、単一アプリ解除、入力中のルール切替と明示的な再選択を確認する。DOM拡大はnative Dynamic Typeの代用合格ではない。Simulator/実機/VoiceOver/実際のgesture/Screen Time・Extension/永続化は未検証。自動画像の生成を人による目視レビューと同一視しない。

## フロー完了と未保存ガード

静的デモで、入力を破棄しても作業画面に留まる経路をブラウザ検証で検出した。戻り先の指定変更では解消しなかったため、既存のtyped帰還処理へ戻し、終了許可・clean draft・Rootの未保存ガード登録がReactのcommitへ反映された後に完了遷移する。破棄/解除受付の両方を配信前のブラウザ操作で検証する。保護を迂回せず、nativeの実gesture/帰還は引き続き未検証。

ブラウザ検証はUbuntu24.04の既存Google Chromeを使い、Playwright本体だけを一時ディレクトリへ固定版で導入する。実際のChrome版はresults.jsonへ記録する。製品dependenciesは追加しない。
