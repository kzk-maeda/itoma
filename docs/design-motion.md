# B案: 静けさに手触りを加えるデモ

状態: ユーザー依頼に基づく視覚・操作の比較PoC。原則を維持しつつ装飾と動きを追加する。今回のデモを本体の実装済み状態やOSの制限成功とは扱わない。

## 入口

- `public/design-motion.html`。ブランチのデモURLに `design-motion.html` を付けて開く。
- ブランチ: `demo/b-native-motion`。最新main `6c17ac9` を基点とし、配信workflowや `demo/**` ガードは変更しない。
- ローカル: `python3 -m http.server 8767 --directory public` → `http://localhost:8767/design-motion.html`。
- 元のB案は [#40 / a5779a3](https://github.com/kzk-maeda/itoma/blob/a5779a3f42ce3acc9cfda99038bb374a2bee729e/public/design-b.html)。元のブランチ・デモ環境は変更しない。

## 採用候補にする3つのアイデア

| ID | 表現 | 目的と範囲 | 動きの仕様 |
| --- | --- | --- | --- |
| M01 | 円弧＋先端の点＋薄い内周目盛り | 制限区間の残り割合を読みやすくする。文字で残時間と終了時刻も表示 | 円弧/先端位置を650msで補間。初回の円は400msで小さくフェード/スケール。秒更新は実際の時刻だけに従う |
| M02 | 本人の目的に、しおりの小さな線画と温かな面 | 引用領域だけにアクセントを絞り、本人が大切にしたいことを見つけやすくする | 静止。呼吸・点滅・反復・パーティクルを使わない |
| M03 | 選択面・押下・遷移への反応 | 選んだ/押した/次の画面へ進んだことを短く返す | 押下140ms・scale .98、選択行scale .99、画面切替180ms・移動5px＋フェード。待機時間や解除条件にはしない |

追加の仕上げ: アプリ状態をグループ面にまとめ、現在の状態を小さなラベルにする。主要ボタンと端末面に浅い陰影を付け、タイマーの数字はtabularにする。深い影・全面ぼかし・複数の強いアクセントは足さない。

円弧の650msは、デモで10分進めたときの大きな差分を視線で追えるようにする比較値。一般操作の120〜180msとは役割を分けた提案であり、[UIガイドライン](ui-guidelines.md)のモーショントークンを自動変更しない。端末での感触を見て採用値をレビューする。

## 操作と比較

1. ホームの円と本人の目的を見る。
2. 端末枠の外の「10分進める」で、90分→80分と円弧75%→約66.7%の移動を見る。これはデモ時計全体を進める操作で、解除中なら解除期限も経過する。
3. 「一時解除する」から別画面でアプリを選び、理由を自由入力して確認・確定する。
4. 「表情を加えたB案」「これまでのB案」を切り替える。切替ではViewを作り直さず、入力・選択・解除期限を維持する。薄い装飾だけで状態を伝えていないか比較する。
5. OS/ブラウザの `prefers-reduced-motion: reduce` で、全アニメーション/transitionを無効にした表示を確認する。設定変更時は実行中のアニメーションも止める。

バックグラウンドへ移ると表示timerを停止し、復帰時に時刻から再評価する。画面上の秒更新や円の動きはOS制限の実行手段ではない。反復する装飾アニメーションは0本。

## 原則・実装ガイドとの対応

- 原則1/3: 本人の目的と現在の時間帯を主役にする。円の文字・終了時刻は常に読み取れる。使用時間や達成率とは表示しない。
- 原則2: 共通入口→別画面の対象選択→自由入力→内容確認。選択/空欄の検証は装飾切替と独立。
- 原則4: Light/Darkの既存配色を土台に、引用領域だけwarmを追加。Light `#EDE5D5`/線画 `#6A5737`、Dark `#34372B`/線画 `#D2C6A8`。本文は既存text色。意味のある入力輪郭はmuted/選択はaccent。押下・選択とも文字やチェックを併用。
- 原則5: 理由を破棄するときに確認し、入力継続/Escapeなら維持する。完了を盛り上げる演出や、画面に留める効果音は追加しない。
- 関連受入条件: UI02/UI04〜UI07/UI09/UI14/UI22〜UI26。対応したPoC範囲で確認し、受入条件全体の合格とはしない。

本体へ採用するときはwarm色とmotion値を `src/constants/theme.ts` に統合する。このPoCのHTML内CSSを新たな本体テーマ体系にはしない。ネイティブの触覚フィードバックはWebでは実装しない。将来の候補は選択が確定した瞬間に1回だけとし、実機で強さと設定への対応を検証してから採用する。

## 今回の機能範囲と限界

解除は元の#40と同じ検証用の一括5分・同時1セッションを引き継ぐ。複数アプリ一括確定の製品採用、個別grantの保存・競合、優先ルールによる期限短縮を追加実装したものではない。理由の最大200文字もデモだけの値。

理由の自由入力は必須で、空白だけでは進めない。未選択のアプリの制限は維持する表示。早期終了・期限到達・ルール終了を試せる。選択/理由がある状態で戻る・継続を選ぶと破棄確認する。理由は画面内のみで保存・送信せず、URL/ログにも出さない。表示上の制限/解除/終了はシミュレーション。
