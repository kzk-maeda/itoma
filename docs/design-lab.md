# デザイン原則を適用した3案の比較デモ

状態: 比較用PoC。原則・解除条件・秒数の正式採用や、OS動作の実証ではありません。

## 入口と狙い

`public/design-lab.html` は依存ライブラリ・外部通信のない単体Webプロトタイプです。Expoのpublic assetとして既存のブランチ別Webデモにも含まれます。本体のReact Nativeホームと設定操作は維持しています。

- ブランチのデモURLに `design-lab.html` を付けて開きます。ブランチURLは `npm run demo:info` で確認できます。
- ローカルでは `python3 -m http.server 8765 --directory public` を起動し、`http://localhost:8765/design-lab.html` を開きます。
- ページ上部でホーム／一時解除／解除中を一括切り替えでき、各案では独立して操作できます。

利用場面は、本人が設定した21:00–23:00のX・YouTube制限中に、21:30にXを使おうとする夜です。「読書」は本人が登録した想定のサンプル文であり、利用者の目的を自動で決める仕様ではありません。各案の一拍の条件も、本人が設定時に選んだ仮定です。設定フローはこのPoCの範囲外です。

| 案 | 情報の順序・表現 | 解除の一拍 | 比較する問い |
| --- | --- | --- | --- |
| A 静かな明快さ | 現在の状態→対象アプリ→終了時刻→操作。明るい面と区切り線で整理 | 目的を選択→解除内容確認 | 短い選択で目的を考えられるか。機械的な選択にならないか |
| B 余白のある伴走 | 対象・終了時刻→本人の目的。紙のような背景と余白、円形の時刻表示 | 問いかけ→解除内容確認。入力必須なし | 思い出す機会になるか。状態の把握が遅れないか |
| C 意思をことばに | 現在の状態→予定の流れ→本人の目的。時間軸で構造化 | 短い自由入力→解除内容確認 | 目的を明確にできるか。繰り返しの入力が負担にならないか |

## 共通の判断

- ニュートラル背景・既存DESIGN.mdのLight/Darkパレット・システムフォントを使う。色に加え、文言・選択印・ARIAで意味を伝える。
- 「制限を続ける」と解除操作の両方に44px以上の領域を確保する。制限継続を主要操作として示し、解除操作も通常の文字コントラストで表示する。
- 解除はXだけ・5分間（仮値）。確定からカウントし、YouTubeの制限は維持する表示。途中終了・期限到達・キャンセルの結果を示す。羞恥や達成演出は使わない。
- A/Cは未選択・空白だけの入力で確認へ進めない。内容の良し悪しは評価しない。入力は画面内メモリのみ。HTMLとして解釈せず、送信・永続化しない。
- 状態不明時は制限中と断定しない。デモ用操作は端末枠の外に置く。
- 端末枠内のホーム表示とルール情報は位置を示すラベルであり、未実装の設定や振り返りへの操作ではない。
