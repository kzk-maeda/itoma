# 制限区間の記録・累計・グラフの実機確認

測定scopeと制約は[ADR0010（Proposed）](../adr/0010-native-recorded-restriction-intervals.md)。この手順は実行結果ではない。iOSの内部遮断秒数を直接計測した値とは区別する。

## ビルド

PRの`feat/restricted-duration`の最新headで、普段使っている実機用の設定・App Group・Teamを使ってnative appとDeviceActivity Extensionをビルドする。JSだけの更新では反映されない。新規entitlementは追加していない。実機の理由文や選択tokenをログやスクリーンショットに残さない。

検証記録にsource SHA、JS SHA、native build ID、構成、端末/OS、JST時刻を記入する。旧buildの結果を本変更の合格にはしない。

## 最小確認

1. 現在を含む時間帯に、試せる対象A/Bを設定して制限を適用する。A/Bの実起動でShieldを確認する。振り返りを開き、初回から過去のデモ時間が加算されていないことを確認する。
2. 電源ボタンで画面をロックして、2分ほど端末を置く。ロックを解除して戻り「最新の記録を確認する」を押し、累計・この週・今日の行が同じ記録時間だけ増え、確認時刻が更新されることを確かめる。スリープ中も進む単調時計を使い、ロック中を時計の飛びとして除外しない。表示は分単位切捨てなので、秒単位の一致を画面だけから判定しない。
3. Aだけ5分解除する。Aを起動でき、BにはShieldが残ることを確認する。途中で振り返りを更新しても、**Aの解除中は全体累計が増えない**ことを確かめる。
4. 約2分でAを早期終了し、AのShield復帰を確認する。その後2分ほど待って振り返りを更新する。解除要求の5分ではなく、実際に記録した解除/不明区間が除かれ、成功確認以後だけ増えることを確かめる。
5. 別の試行で5分の解除を期限まで待つ。予定期限を過ぎただけでは計上を再開せず、nativeの再制限成功後の時間から増えることを確かめる。hostを終了した状態でもExtensionで再制限されるかを別に記録する。
6. 月次→週次→前後の期間へ移動し、上部の全体累計と推移が変わらないこと、期間別の棒・数値・日別履歴への移動が保たれることを確認する。

開始/解除操作/解除確認/早期終了/再制限確認/更新の時刻を記録する。操作開始や結果確認に時間がかかる分は保守的に除外されるため、壁時計だけで「ちょうど115分」とは判定しない。115分/118分などの正確な算術は固定時刻のnativeテストで検証する。

## 不明・停止・削除

- 全体停止→数分後に明示再開：停止中は増えず、再開の成功確認後から増える。
- 認可取消→再許可：取消を観測した区間を加算せず、本人の再開確認を保持する。取消/再許可が観測間で完結する場合の全検出は保証しない。
- 再起動/時計・zone変更：不連続をまたぐ未確認区間を埋めず、一部不明の表示で新しい区間へ移る。
- 理由のみ/操作履歴のみ削除：累計は保つ。全記録と累計の削除：旧数値を消し、古い取込・画面応答・期間移動で復活しない。既存の制限/解除は勝手に変更しない。
- Light/Dark、最大文字、VoiceOver、Reduce Motion：時間と確認範囲を読める。タブや週/月の移動で画面stack、timer、保存件数が際限なく増えない。

実機からDBを読む場合は必要な数値/不透明ID/時刻だけを検証に使い、理由・native token・目標の文章を外部へ送らない。失敗時は画面のエラー分類と該当buildを残す。
