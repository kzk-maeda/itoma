# 主要体験の改善デモ

本人依頼の3論点を比較する独立Webデモ。Issue #199、`demo/core-experience`。main `30b91c7` 基点。本体/native/正式サイトに変更なし。

## 体験の変更

1. ホームは確認した状態→ルールと残時間→次の操作→目的→対象の順。反映未確認は回復操作を最上部に出し、保存した予定を制限中と断定しない。技術的な説明はdetails内で読む。
2. 共通の解除入口から、アプリ選択→自由入力の理由と1〜30分→対象・理由・実際の上限・続ける制限の確認へ進む。「制限を続ける」を維持。空欄への不足表示は操作後で、該当欄へfocus。編集/ブラウザー戻るで入力を保持し、離脱は破棄確認。複数アプリの要求を個別に保持する。
3. 記録の初期表示は操作履歴。デモ内の確定操作と理由を確認でき、サンプルの設定記録は別に開く。未接続の累計・週次・月次は時間の集計タブで準備中と伝え、架空の成果や0分の代用を表示しない。

固定OPEN CIRCLEとU07墨と白を使用。Web用CSSの色値は本体GraphiteColorsと一致。原則1〜5、U02/U03/U04/U05/U06/U07、UI03〜UI16/UI22〜UI26/UI30/UI35/UI36の検討。追加の待機・料金・AIによる採点はない。

## 試し方

- ホームから一時解除→X選択→理由/時間→確認→確定→ホーム→記録。YouTube等も続けて解除できる。
- 上部の「状態を試す」で未確認/停止や解除結果を切り替えられる。再開は設定内容の確認を経て行う。
- 「時計を5分進める」で期限終了の記録へ。期限後の再制限は未確認として表示し、OS成功を捏造しない。反映結果の確認で解除の期限を延長しない。確認画面の期限も固定し、超過後は再確認が必要。
- 記録から理由を開く。時間の集計は準備中であることを確認する。

## デモと実装の境界

すべて架空の設定・記録で、デモ時計は21:30開始の手動時計。実OS反映・永続化・ルール競合・native command受理の検証ではない。通常の時計/日跨ぎ/複数ルール・再起動復元は本体設計と実機検証に従う。

入力理由はタブ内の一時メモリーだけ。URL/ログ/通信/Web Storageに保存しない。再読込・リセットで消える。操作記録はデモの要求・確認結果であって、集中の成果やアプリ利用時間ではない。失敗時の保存のみ記録と、未確認の要求を区別する。

デモ画面ではHTMLの標準button/textarea/dialogを使用。本体のExpo Routerは変更しない。配信時に `public/demo-entry.json` の同ディレクトリHTMLをindexへコピーし、一覧からルートを開いても本デモに到達する。検証済みの同方式をPR188から必要部分だけ移植。正式サイトPR192は含めない。
