# 保存・共有・プライバシー

状態: **提案・未確定**。検討Issue: https://github.com/kzk-maeda/itoma/issues/25。この文書は実装・OS動作の保証ではありません。


## 保存境界の初期案

| データ | 所有・共有候補 | 検討事項 |
| --- | --- | --- |
| 対象選択トークン | ネイティブ保存、必要時だけApp Groups | エンコード、権限取消、破損。生の識別子取得を前提にしない |
| 確定policyとrevision | 本体/Extensionが読む共有保存候補 | 更新の正本、原子的置換、整合性 |
| 解除期限と処理ID | 本体/Extensionの共有候補 | 競合、期限、再試行、古いイベント |
| 適用結果・観測時刻 | ネイティブ状態候補 | 鮮度、観測限界、復旧 |
| 履歴 | 端末ローカル | 最小種別、保持期間、削除、上限 |
| 編集途中の選択 | 画面メモリ | 取消で確定値を変更しない |
| 解除理由の文章 | 保存しない案を含め比較 | 必要性・センシティブ性・削除 |

DB製品、UserDefaults、ファイル、Keychainなどの採否は未決定です。共有性、原子性、移行、利用するデータ型、Extension制約で比較し、ADRを作ります。

## 更新・復旧で決めること

schemaVersion / revision / operationIDの意味、共有ロックまたは競合検出方式、OS操作との順序、アプリ更新時の移行、移行途中のExtension読み取り、データ破損時の復旧と本人への説明。

## プライバシー上の前提

外部送信・分析SDK・バックエンドは前提にしません。不透明トークン、理由本文、端末識別情報をログやPR証跡へ出しません。iOSから取得できない全アプリの起動回数を記録できると扱いません。

## 試験項目

保存失敗、同時更新、途中書込み、破損、旧schema、移行失敗、再起動、削除、ディスク制約、OS適用と保存の片方のみ成功。削除操作がOS制限に与える影響もルールと合わせて決めます。
