## 了承済みの7項目

1. **競合のtotal order**：全ruleの一意な優先順を保存前に本人が確認・確定する。対象ごとの逆順は初版対象外。
2. **解除の終端**：次の優先切替・現occurrence終了までを上限とし、短くなる場合は事前に説明。失効grantは復活させない。
3. **構成**：小さいMVVM＋共通Swift評価層。React標準のhook/reducerから始める。MVVMとReduxは併用可能で、Reduxが二重正本を必然的に生むわけではない。初版は追加依存・同期処理を増やさない。
4. **保存先**：shared control SQLiteと本体private理由・履歴SQLiteを分ける。保護・プロセス競合・受渡し・復旧は実機PoCで確認する。
5. **保持・容量**：自動期間削除なし、本人削除、容量警告と新規payload停止。80MiB/100MiBは実測後に確定する暫定値。履歴障害だけで再制限・本人の停止を妨げない。
6. **追加の摩擦**：初版は解除回数制限・追加待機なし。ダミー金額候補は後続UIレビューで判断し、実際の請求は行わない。
7. **未保存編集とOS終了**：通常の戻る/閉じるは破棄確認、アプリ切替ではメモリ保持。OS強制終了後のDraft復元は初版対象外。

この了承は下記P1/P2の解消・実装完了・実機合格を意味しない。DST解決等の詳細仕様やoutbox1万件は個別の了承済み事項と混同せず、本設計PRのレビュー対象として残す。

## PoCで否定され得る仮説

- App Groups内のSQLiteと短いwriter区間で、本体/Extensionが競合・killから回復できる。
- 共有Swift評価層をExpo Module本体と各Extensionへ無理なく組込める。
- 自分のOS設定の反映を短い同期区間で扱え、観測できる範囲を正直に返せる。
- OSイベントと永続した絶対期限で、本体停止中の再制限が必要な精度で成立する。
- File Protectionとバックアップ除外が全付随ファイルにも適用でき、最初のアンロック前の制約を説明できる。

不成立なら #26 に証拠を残してADRを再検討する。未実施を「Acceptedだから動く」と扱わない。
