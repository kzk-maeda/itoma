## 2. 体験モデルと責務

プロダクトの軸は「本人が決めた時間帯ルールで対象群を制限し、必要なときに理由を言葉にして必要なアプリだけ使う」。全アプリに唯一の時間帯を強制する意味ではない。

| 層 | 持つ情報・責務 | 持たせないもの |
| --- | --- | --- |
| Rule | 対象集合、曜日・時間帯、解除条件。アプリごとの有効ルールの判定はEvaluator側 | UIのカード順や理由入力中の値 |
| Grant | 対象1つ・rule/version・今回の区間・絶対期限・適用状態（#36依存） | 「全アプリが5分間開ける」という単一フラグ |
| ViewModel | snapshotから表示用の行・区間・操作可否を導出。draftとcommand表示状態を保持 | ルールの勝者判定、OS反映保証、別の期限の正本 |
| View | 表示・入力・フォーカス・イベント通知。可視の間だけ残時間を再表示 | OS制限、JSタイマーによる再制限、理由の永続化 |

UI用型の例。実在するBridge API/OS enumの宣言ではなく、ViewModel→Viewの入力契約の提案。採用したドメイン型からadapterで変換し、TSにSwiftの評価ロジックを複製しない。

```ts
type TargetRow = {
  targetID: string; // ドメインの不透明ID。アプリ名を識別子にしない
  label: string;   // nativeで利用可能な表示情報。取得不可なら「選択したアプリ」
  state: 'scheduled' | 'restricted' | 'releasing' | 'released'
    | 'restoring' | 'failed' | 'unknown'; // UIだけの表現
  stateText: string;
  detailText?: string; // 終了日時、解除できない理由等
  actions: ('selectForUnlock' | 'viewGrant' | 'retry' | 'editRule')[];
};
type RulePeriod = {
  ruleID: string;
  occurrenceID: string;
  title: string;
  startsAt: number; // epoch ms、Evaluatorが確定した今回の区間
  endsAt: number;
  targets: TargetRow[];
};
type UnlockDraft = {
  targetID: string | null;
  reason: string;
  requestedMinutes: number; // 設定値を初期表示。5をUIへ直書きしない
  baseRevision: string;
};
```

`actions`は認可・Activation・ルール・command/grant・観測状態を考慮したドメイン結果から組み立てる。`state === 'restricted'`だけで解除許可と推測しない。最終確定時はnative側で再検証する。

## 3. 画面・情報順・ルート

以下はExpo Routerで実装するルート案（P03）。既存のモックホームは `src/app/index.tsx` → `src/components/home/home-screen.tsx`。本書を理由にスターター画面へ機能を混在させない。

| 画面 | ルート案 | 上からの情報順 | 操作と終了条件 |
| --- | --- | --- | --- |
| H ホーム | `/` | 適用上の問題→ルール名と円→本人の目的（登録時のみ）→対象行→共通の解除入口→ルール設定入口 | 現在対象・時間・次の操作が理解できる。履歴・達成演出を置かない |
| U 選択・理由 | `/unlock` | 戻る→問い→対象選択→理由入力→解除時間→継続/確認 | 有効な対象・空白以外の理由・許容時間が揃うと確認可 |
| C 内容確認 | `/unlock/confirm` | 戻る→対象→適用ルール→実際の終了上限→理由→残る制限→継続/確定 | command受理前は確定設定・grantを変えない |
| G 解除状況 | `/unlock/status` | 対象と処理結果→残時間/絶対期限→残る制限→早期終了/ホーム | Active以外を解除済みと表示しない |
| R ルール一覧・編集 | `/rules`, `/rules/[id]` | 対象→曜日・開始/終了→解除条件→目的（P07採用時のみ任意入力）→重複/影響→取消/保存 | 確認済み条件だけ反映。目的未登録は許可 |
| A 認可・再開 | `/permissions` | 必要性/現在の認可→保存済み設定への影響→OS認可/戻る。再認可後は再開確認 | 拒否しても戻れ、再認可だけで自動再開しない（#36依存） |

ルート案の`[id]`以外の引数を含め、理由本文・アプリtokenをURL、ルートparams、解析イベント、ログ、testIDへ入れない。draftはフロー寿命のViewModelに置く。画面移動で再生成しない。

ホームでは共通入口「一時解除する」を1つ置く。別アプリのgrantがActiveでも、他の対象の操作可否はアプリ単位で扱い、デモの「同時に1セッションのみ」を製品仕様へ移さない。可否はドメイン判定に従う。Active行の「解除状況を見る」は状態確認への入口であり、新たな解除ボタンではない。

ルール編集の「停止」は一時解除と区別する。保存/停止で解除が終わる・他ルールが残る場合は影響を先に確認する。失敗しても希望設定を黙って初期化しない。優先順の確定UIは#36の採用版に従う。

## 4. ホームと円の厳密な仕様

### 4.1 ホーム状態の表示表

| 状態 | 主表示 | 円・対象 | 主な操作 |
| --- | --- | --- | --- |
| 初回・ルールなし | 「制限する時間を決める」 | 円なし。モックの制限中を作らない | 「ルールをつくる」 |
| 設定済み・未認可 | 「制限を適用するには許可が必要です」 | 設定上の対象・予定として表示 | 「許可を確認する」/設定編集 |
| 許可後の再開待ち | 「制限を再開しますか？」 | 保存済みルールを要約。制限中の断定なし | 「内容を確認して再開」/「今は再開しない」 |
| 有効な区間なし | 「今は制限時間外です」 | 円なし。次の開始と対象。予定なしならその事実 | 「ルールを確認する」。対象のない解除入口を出さない |
| 区間が有効・観測は利用可能 | ルール名と「アプリを制限中」 | 当該区間の円。対象別に制限/解除を明示 | 「一時解除する」/設定 |
| 一部解除 | ルール名と「一部のアプリを一時解除中」 | 円は**ルール終了まで**を維持。対象行に解除期限 | 共通解除入口とActive行の状況確認 |
| 全対象が一時解除中 | 「対象アプリを一時解除中」 | 円はルール区間の残り。対象を制限中と書かない | 各grantの状況確認/設定 |
| 反映中/再制限中 | 「反映中です」/「制限に戻しています」 | 最後の確認状態と今回の処理を分ける | 状況確認。処理中の同じ操作は重ねない |
| 失敗/古い観測/不明 | 「設定を反映できませんでした」/「制限の状態を確認できません」 | 希望設定・最後の観測時刻を併記。時間の円は「設定上の時間」と明示するか隠す | 状況確認/本人の再試行/設定 |

認可・Activation・適用状態を1つのboolへ押し込めない。表示上は「復旧を要する問題→今回の処理→時間帯と対象」の順で問題を先に知らせる。OS全体の制限を証明できない観測は、その範囲を状況詳細に表示し、証拠以上の成功を断定しない。

### 4.2 円が意味するもの

- 見出しにルール名を付ける。中心のラベルは「この時間帯の終了まで」、値は「1時間30分」、補足は「23:00に終了」。日跨ぎは「翌02:00に終了」。これ以外の場所へ同じ開始・終了バーを追加しない。
- `remainingMs = max(0, endsAt - now)`、`remainingFraction = clamp(remainingMs / (endsAt - startsAt), 0, 1)`。非正の区間は円を描かず不正なデータとして復旧表示する。nativeが渡した区間に対する表示計算のみ。
- 21:00開始・23:00終了・21:30現在なら90分、円弧75%。円は使用時間・集中達成率を示さない。実際の利用を推測して「90分取り戻した」としない。
- 1分以上は残分を切り上げ、60分以上は時分表示。60分ちょうどは「1時間」、1分未満の正値は「1分未満」。0は円を終了状態へ切り替え、次snapshotを取得する。OS再制限成功とは扱わない。
- grantの残時間は別要素で `expiresAt-now` を計算し「一時解除の残り」と明示。5分未満は `m:ss`、期限の現地時刻も表示する。期限到達時はExpired/再制限処理を再取得し、成功の推測をしない。
- 複数ルールがある場合（P02）、区間を開始日時→ruleIDの安定順で並べる。同一対象の有効ルールはEvaluatorの結果を使い、下位ルールの予定を現在有効と混同しない。1円に複数の終了時刻を混ぜない。カード名から対象行の適用理由をたどれるようにする。
- フォアグラウンド/フォーカス復帰時に最新snapshotと時刻を再取得。表示更新timerは可視の画面で最大1本、離脱時に破棄。残時間の値だけを更新して入力やフォーカスを再生成しない。
- 円の読み上げは「夜の時間、この時間帯の終了まで1時間30分、23時に終了」。SVG装飾は非アクセシブル。毎秒のlive announcementをしない。値は文字でも読める。

## 5. 解除フローの操作契約

### 5.1 選択と入力

P01を採用する場合、未選択で開始する単一選択リストとする。各行はアプリ名・現在の状態・適用ルール・解除できない理由を持つ。ラジオの選択状態をVoiceOverへ渡す。アプリ名やアイコンが取得できない場合のnative代替表示を使い、推測でX等に置き換えない。

制限中・操作可能な対象だけ選択できる。一時解除不可、Pending/Active/Uncertainな同対象は選択不可とし、「この時間帯は一時解除できません」「反映を確認中です」「解除状況を見る」など、理由または状況確認を行に残す。表示から無言で消さない。時間外の対象へ新grantを付与しない。

入力ラベル「いま使う理由」、例「友人からの連絡を確認する」。複数行入力で日本語IME・改行を許可。placeholderをラベルの代用にしない。`reason.trim().length > 0`を空欄検査の基準とし、内容の採点・禁止語判定を足さない。デモの200文字上限は確定要件ではない。保存側と一致する最大長を#25で決め、超過は説明付きで拒否して黙って切り捨てない。

解除時間は採用版の設定値を表示する。#36では初期5分・上限30分が本人回答、共通1〜30整数分は提案。UIはその採用範囲内で編集し、範囲外をnativeでも拒否する。追加待機・回数予算を導入しない。

確認ボタンの有効条件は「対象選択済み・理由空欄でない・時間有効・前提有効・受理中でない」。無効理由をボタン付近の文で示す。フォームエラーを色だけで示さず、入力値を保持する。

### 5.2 確認と確定

確認画面は、対象名、適用ルール、要求した期間、境界で短縮される場合の実際の上限/終了日時、理由、残る制限の順。例「Xを最大2分、22:00まで解除します。22:00から別のルールが始まります」。5分と見せたまま2分で終えない。

確定前にrevision・対象・優先ルール・認可・期限を最新値で検証する。確認中に変わった場合は「条件が変わりました。内容を確認してください」と差分を出し、draftを保持して再確認する。以前の確認内容で別ルールのgrantを発行しない。受理時に保存された絶対期限が正本で、再表示・再試行で5分に戻さない。

操作の視覚階層は次のとおり。意味上の`primary`は単に左側の操作を指すものではない。

| 場面 | 主操作（塗り） | 副操作（枠） | 注意 |
| --- | --- | --- | --- |
| ホーム | 一時解除する | ルールを確認する | 入口で即解除しない |
| 理由入力 | 制限を続ける | 解除する内容を確認する | 副操作も本文と同等の文字コントラスト |
| 内容確認 | 制限を続ける | 「Xを最大2分解除する」等 | 「OK」「続ける」だけで確定させない |
| 適用中 | 状況を表示 | ホームに戻る | 確定ボタンを無効化し二重付与を防ぐ |
| 解除中 | 今すぐ制限に戻す | ホームに戻る | 戻る操作はgrantの終了を意味しない |

ダミー課金モードの場合は確定前に「模擬操作・実際の請求なし」と金額を表示する。理由必須を全モード共通にするか、理由モードのみか、金額候補・選択方法は別レビュー。自由入力の要望を根拠に課金案を削除したり、未合意の全モード必須化をしない。一時解除不可なら理由入力で迂回できない。

### 5.3 遷移と非同期結果

| イベント | 次の画面・表示 | draft/command/grantの扱い |
| --- | --- | --- |
| ホーム→解除 | U | 新draft。対象未選択。理由を過去履歴から自動入力しない |
| U→C→U | 確認→編集 | 全draftを保持 |
| dirtyなU/Cで戻る・閉じる・制限継続 | 「入力内容を破棄しますか？」 | 「入力を続ける」「破棄して制限を続ける」。承認まで破棄しない |
| 未編集で戻る | ホーム | 確認不要。確定値は不変 |
| アプリ切替 | 現画面を保持 | draftは保持。OS強制終了前の確認・draft復元は保証しない（#36依存） |
| 確定 | Gの反映中 | commandIDを1回作成。受理後に画面を離れても処理所有者はnative |
| Pending/Applying | 「解除を反映しています」 | タイマーだけで成功へ移さない。戻る操作はcommand取消ではないと説明 |
| Active | 「Xを一時解除中」 | 保存された期限から残時間表示 |
| Failed | 「一時解除を反映できませんでした」 | 設定・draftを保持し、本人の再試行へ。nativeの可否に従う |
| Uncertain | 「解除の反映を確認できません」 | 新commandで迂回しない。状況確認または同一commandの許可された再試行 |
| Expired/Invalidated | 「解除期間が終了しました」「ルール変更で解除が終了しました」 | OS再制限待ちなら「制限に戻しています」。観測確認後に結果を更新 |
| 早期終了 | 再制限中→結果 | ボタン押下だけで「制限中」にしない。別アプリのgrantは終了しない |

gesture戻り・ヘッダー戻り・閉じる・「制限を続ける」は同じ破棄判断を通す。モーダルの外側タップでdraftを無言で消さない。反映済みcommandにdraft破棄を適用しない。

## 6. 見た目をコードへ移すためのトークン

色は本人が選んだU07「墨と白」の採用値、寸法/部品はP03、動き/影はP08として区別する。新画面でハードコードを増やさず `src/constants/theme.ts` に統合する。既存home内の緑paletteと同ファイルのスターターテーマが不一致なので、移行PRで利用箇所を確認して一本化する。キー名だけ変えて緑やスターターの色を流用しない。今回の資料変更はテーマの実装完了を意味しない。

### 6.1 色

基本配色は05「墨と白」（`graphite`）。根拠は [5案比較 #62 / fd0ddb6 の配色定義](https://github.com/kzk-maeda/itoma/blob/fd0ddb6/public/color-palettes.js) を見た本人の選択「05がいいね」とガイドへの反映依頼。以下と§6.4の目的面が1組であり、主ボタンだけの差し替えにはしない。Light/DarkはOS設定に従う。比較用の配色切替機能を製品へ追加する判断は含まない。#40/#60の緑・warm色は過去の比較資料であり、現在の基本色ではない。

| トークン | Light | Dark | 用途 |
| --- | --- | --- | --- |
| background | `#F4F3F0` | `#1B1C1A` | B案の画面の土台 |
| surface | `#FFFFFF` | `#292B27` | 入力・選択面 |
| text | `#30312F` | `#F0F0E9` | 本文・枠ボタン文字 |
| muted | `#666762` | `#BDBFB6` | 補足。opacityでさらに薄めない |
| line | `#DDDDD6` | `#4D5048` | 装飾・区切りのみ。必須の入力境界や選択印には単独使用しない |
| accent | `#444842` | `#CDD2C4` | 主ボタン・選択印・円弧・フォーカス |
| soft | `#E7E8E1` | `#3A3E35` | 選択背景・状態要約 |
| onAccent | `#FFFFFF` | `#23271F` | 主ボタン文字 |

非テキストの意味を担う入力枠・選択輪郭・フォーカスは背景と3:1以上。`line`が満たさない箇所は`muted`/`accent`を使う。失敗は専用色だけで伝えずアイコンと短い説明を付ける。新しい警告色が必要なら両モードのコントラストを記録して追加する。

### 6.2 寸法・文字・動き

| 名前案 | 基準値 | 使用条件 |
| --- | --- | --- |
| space | 4 / 8 / 12 / 16 / 24 / 32 | 既存Spacingの互換を確認して統合。画面左右24、関連部品12、セクション24 |
| typography | title 28/40 medium、section 20/30 medium、body 16/26 regular、label 14/22 medium、caption 13/20 regular、timer 32/44 regular | 数字はfontSize/lineHeight（pt基準）。iOS system font。大きな文字を縮小して収めない |
| radius | input/button 12、group 20 | 同役割は同値。円以外を過剰なpillにしない |
| actionMinHeight | 50、hitAreaMin 44×44 | 固定heightで文字拡大を切らず、minHeightと上下padding12を使う |
| rowMinHeight | 56 | 行全体を選択領域にする。長いアプリ名は折り返す |
| border | decorative 1、focus 2、ringProgress 3 | 最小値。文字・選択状態は別に伝える |
| ringDiameter | 200（通常）/176（狭い幅の目安） | 固定位置へ文字を絶対配置して潰さない。文字拡大時は円を拡張、収まらなければ文字を円の下に分離 |
| contentWidth | iPhoneは全幅−左右余白。iPad等は最大480 | デモの端末枠・サイド説明・比較スイッチを製品UIへ移さない |
| motion | 用途別。§6.3を参照 | 押下/画面遷移の短い応答と、円弧の時間差分の補間を分ける。120〜180msを全用途共通にしない |

Safe Areaを確保したスクロール画面を基本とする。キーボード表示時も理由入力・エラー・確定/キャンセルへ到達できるようにする。操作領域を画面下に重ねるなら、その高さとinsetをcontent末尾へ加える。小さい画面で「制限を続ける」を画面外に固定しない。

### 6.3 モーションの役割・トークン・中断契約

方針U06を実装するときの共通契約。下表の値は#60のWeb比較を起点とするP08で、iOSでの推奨確定値・効果の実証ではない。候補値は `src/constants/theme.ts` の用途別トークンへ統合し、画面や部品に別々の数値を直書きしない。今回の文書変更ではテーマ・部品は実装しない。

| トークン名案 | 適用する場面 | #60を起点にした候補値 | Reduce Motion |
| --- | --- | --- | --- |
| motion.feedback | 操作可能なボタンの押下/離す | 140ms、ease、scale .98→1。選択行は .99→1 | スケールなし。押下の面/枠の静止変化を維持 |
| motion.transition | 選択・確認・状況画面への内容切替 | 180ms、ease-out、移動5→0ptとopacity .55→1 | 移動/フェードなしで内容を置換 |
| motion.periodChange | 時刻差分による円弧・先端位置の更新 | 650ms、cubic-bezier(.22,.68,.22,1)、現在の表示位置→最新の残り割合 | 補間せず最新値に直接更新 |
| motion.periodIntro | 最初にホームの円を見せるときだけ | 400ms、cubic-bezier(.2,.7,.3,1)、scale .97→1、opacity .4→1 | 最初から最終の静止表示 |

650msは大きい時間差分も追えるか比較するための値であり、解除時の待ち時間ではない。ネイティブ標準の画面遷移を使う場合はOSのトランジションと上表を二重に重ねない。画面の再マウントや再表示ごとに導入演出を再生せず、制限の開始や進捗をリセットした印象を避ける。

- **状態が先、描画が後。** 入力・ボタンの操作可否・command受理・expiresAtはアニメーション完了callbackに依存させない。装飾の終了まで確定/取消/戻るを待たせない。見出し・対象・期限などの重要な説明を演出後に初めて出さない。
- 円弧と先端は§4.2の同じ`remainingFraction`から更新し、逆回転・バウンド・オーバーシュートで残時間を誇張しない。数字は最新時刻を即時反映する。先端の点と目盛りは装飾として読み上げから除外し、常時の回転・呼吸・点滅・光の周回を足さない。
- 新しい値が途中で届いたら現在の見た目から最新値へ置換し、古い演出をqueueへ積まない。期限0で演出が残っていても期限状態を先に更新する。期限を延長して帳尻を合わせない。
- 押下を外す・gestureを中断する・無効になる場合は通常の見た目へ戻す。押下の演出だけで選択確定やOS適用成功を示さない。選択・無効・反映中・失敗は既存の文言/印/状態契約を使う。
- 非表示/バックグラウンドでは表示timerと不要なアニメーションを止める。復帰時は最新snapshotと時刻へ合わせ、見ていなかった時間の演出を早送り再生しない。これは表示の制御であり、nativeの期限処理を止める意味ではない。
- Reduce Motionは起動時だけでなく設定変更にも追随し、実行中の移動/スケール/円弧補間を止めて最新状態へ合わせる。処理中は静的な文言で伝えられるようにする。アニメーションを無効にしてもdraft・commandID・対象・期限・選択・フォーカスの論理状態を変更しない。
- 触覚フィードバックは実機確認後の別候補。将来導入する場合も選択確定など意味のある瞬間に限定し、連続発火・音・新たな解除条件を足さない。Webデモで触覚を検証したと記録しない。

### 6.4 アクセントの役割・トークン・配置契約

画面全体は§6.1の「墨と白」のbackground/text/accentを使い、温かな面は本人の目的など**一つの意味のまとまり**に絞る。同じ画面の全カード・見出し・ボタンを一斉に目立たせない。優先する情報は問題/状態→時間→本人の目的→対象/操作のままで、警告・不明・確認内容が装飾に負けないようにする。

| トークン名案 | Light基準 | Dark基準 | 適用範囲 |
| --- | --- | --- | --- |
| purposeSurface | `#E7E2D9` | `#37362F` | 本人の目的の引用面。選択状態/警告/解除成功の色に流用しない |
| onPurposeSurface | text `#30312F` | text `#F0F0E9` | 引用本文。実際の本人データがなければ面ごと省略 |
| purposeMotif | `#656052` | `#CEC8B8` | しおり等の小さい線画。装飾であり、情報は本文で伝える |
| elevation.subtle | 中立な黒、opacity .03〜.06、offsetY 2〜3pt、blur 6〜8ptを比較（P08） | 同じ値を自動流用せず境界線を優先して比較（P08） | 操作面の区別を補助。太い影・多段の影を常用しない |

「墨と白」の文字色ペアは#62の比較検証で最低Light 4.63、Dark 5.88。基本色の採用と実機での可読性検証は別であり、アプリ全体の適合を宣言しない。影・透過・押下状態を含む実際の合成後の背景で再確認する。過去の緑/ベージュの色ペアやその計算値を、現在の採用色の証拠として使わない。

小さい線画は本人の目的に関連するモチーフを1つ置く。機能アイコンや対象アプリアイコンと混同させず、アクセシビリティでは装飾として扱う。アイコンを外しても文脈が伝わること。影を消しても操作可能な領域が分かり、色を見分けにくくても選択印と文言で状態が分かること。

押下・選択・フォーカス・無効は別の状態とする。押下は一時的な面/スケール、選択は印と輪郭、フォーカスは見えるアウトライン、無効は操作不可と理由で示す。影・色・動きだけでこれらを兼用しない。

## 8. 文言とアクセシビリティ

| 意図 | 基本文言 | 避ける文言 |
| --- | --- | --- |
| 問い | 「いま、何のために開きますか？」 | 「また開くのですか？」 |
| 空欄エラー | 「いま使う理由を入力してください」 | 「正しい理由を入力してください」 |
| 制限の根拠 | 「あなたが設定した『夜の時間』のルールです」 | 登録していない目的の押し付け |
| 確定 | 「Xを最大2分解除する」 | 「OK」「がんばる」 |
| 不明 | 「解除の反映を確認できません」 | 未確認なのに「解除しました」 |
| 他のルール | 「仕事中のルールが適用されるため、解除できません」 | 「エラー」のみ |

本文・補足・ボタン文字は4.5:1以上。色だけで選択を示さず、印・文言・accessibilityStateを併用。読み順は画面の情報順と一致させる。入力のlabel・hint・errorを関連付け、エラー発生時に最初の該当入力へ誘導する。処理結果は1回通知し、秒更新は読み上げ続けない。

画面遷移時は見出しへ、破棄確認を閉じたら元操作へフォーカスを戻す。iOSのジェスチャー、VoiceOver、最大のアクセシビリティ文字サイズ、キーボード、Light/Darkは実機/Simulatorで別に確認する。WebのDOM検証をiOS合格として記録しない。

| #40デモ | 製品UIへ移す際の処理 |
